# Artifacts

Deep records, design documents, research notes, and strategic analyses. Artifacts are the long-form thinking layer — when a topic needs more depth than a thread or inbox item can carry, it becomes an artifact.

## When to create an artifact

- A design decision that needs a written argument (options considered, trade-offs, rationale)
- Research or analysis that took significant effort and should be preserved
- Strategic assessments or project evaluations
- Implementation plans for complex features
- Post-mortems or retrospectives

## How to create one

Ask your AI coding agent:

> "Write an artifact analyzing [topic]. Save it to `.gator/artifacts/` with today's date."

Or be more specific:

> "Create a design artifact comparing approach A vs approach B for [feature]. Include trade-offs and a recommendation."

## Naming convention

`YYYY-MM-DD-descriptive-title.md` — the date prefix keeps artifacts sorted chronologically and prevents name collisions.

## What artifacts are not

Artifacts are not task lists (use roadmap or inbox), not code documentation (use charters), and not ephemeral notes (use threads). They are the permanent record of thinking that shaped the project.
