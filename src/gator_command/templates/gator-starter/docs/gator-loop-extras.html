Notes for specific AI models in a Gator loop: what each model does well, and any setup it needs.

Codex (OpenAI)

Tested with GPT-5.6-terra, medium reasoning.

  • Works well as the Reviewer. Codex checks the Draftor's plans and code before they are approved.

Start Codex with gator loop codex

  1. Open a terminal in the repository root and run: 
    gator loop codex
    Gator prepares a separate Codex profile for loops (~/.gator/adapters/codex/loop-home) and starts an interactive Codex session in the repository. The first time, Codex asks you to sign in to this profile.
  2. Join the loop. Give Codex the participant prompt for its role from the Loop workspace.
  3. Enter the goal prompt below in the same Codex session. Codex then stays in the loop until it ends.
Trust cost

In this profile, five routine commands (gator loop status, wait, submit-draft, submit-review and submit-implementation) run outside the Codex sandbox, with your full user rights and without a prompt. Everything else still follows the normal Codex rules. To see what the command would change before you run it, use gator loop codex --dry-run. The command works on Windows only for now.

Keep Codex in the loop with /goal

Paste this into the Codex session after it has joined the loop.

/goal Remain an active participant in the Gator loop I just joined until it reaches a terminal state. Follow the Gator loop protocol exactly. If it is not my turn, use the existing role token and reissue `gator loop wait --token <token> --max-seconds 360` whenever it returns exit code 3. Stay connected through paused and blocked states. When my turn arrives, perform the required governed review or submission through the CLI. Stop only on terminal exit code 2; do not edit loop files directly or submit without completing the required work.

Copy did not work here. Select the prompt above and copy it.

  • Leave <token> as it is. Codex uses the role token from its join. Do not paste the token into the prompt.
  • Why the wait is 360 seconds. 360 is the protocol default. Each wait that ends without a turn costs Codex a model turn, and a long interval keeps that cost low. The wait returns as soon as it is Codex's turn, so it does not delay the loop.

Opus (Anthropic)

Tested with Claude Opus 5.5.

  • Works well as the Draftor. Opus writes clear plans and implementations for the Reviewer to check.
  • No extra setup. To join the loop, copy the participant prompt for its role from the Loop workspace and paste it into Claude Code. Opus waits for its turn with a background watcher, so it needs no goal prompt.
