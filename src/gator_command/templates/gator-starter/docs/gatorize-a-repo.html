This Dashboard runs from the Gator CLI on your machine, so Gator is already installed. Each repository needs Gator added once.

1. Add the repository to your fleet

  1. Open Fleet in the sidebar.
  2. Click Add Repository.
  3. Gator scans common locations for Git repositories. Find yours under Repos found and click Add. If it is not listed, type its folder path and click Register.
  4. The repository appears in the Fleet table.

2. Gatorize it

Before you start

Commit or stash your work first. The Dashboard runs Gatorize without prompts, and Gatorize stops if the repository has uncommitted changes. For the cleanest undo, create a branch first, for example git checkout -b add-gator. Gatorize works on whatever branch is checked out.

  1. In the Fleet table, open the ⋮ menu at the end of the repository’s row.
  2. Choose Gatorize.
  3. Wait for the activity indicator on that row to finish. If Gatorize fails, the Dashboard shows the reason.
  4. The repository is governed. The same menu now offers Update when a newer Gator release is available.

3. What Gatorize does

Gatorize adds files in two places: inside the repository, and in a per-machine folder in your home directory. It does not change your source code or your commit history.

What Gatorize leaves alone

Your source code, your existing commits, and your agent instruction files: CLAUDE.md, AGENTS.md, GEMINI.md. Gatorize also does not commit anything. Review the new files and commit them yourself, or ask your agent to do it in the first session.

4. Your first session

  1. Open a terminal in the repository root, the folder that contains .git.
  2. Start your coding agent there: Claude Code, Codex, Gemini CLI, Cursor, or another capable agent.
  3. Paste the session-opening prompt: 
    Run gator init in this repository. Treat its output, including the required session-opening reads, as binding. Do not provide a substantive response until those reads are complete.
    The Start a session with Gator tab has a button that copies it for you.
  4. The agent runs gator init. It then reads the Gator entry document, the constitution, and the mission, roadmap and inbox.
  5. The charters/ folder is empty, so the agent follows the bootstrap procedure. It asks what the project is and whether it is solo or team work. It looks for existing knowledge such as ARCHITECTURE.md, decision records or AI instruction files, and asks before it migrates any of it. It fills in mission.md and roadmap.md, finds the module boundaries (usually 3 to 8 charters), and writes the first charters, their index, and a cross-cutting charter for rules that span modules.
  6. Review the map and commit it. From now on, every session starts from the map.

The first session is an investment. The agent spends it reading your code so that later sessions do not have to. Read the charters it writes: they are the agent’s understanding of your system, and you can correct it before it guides any change.
