# Reference Notes

Cognitive aids, vocabulary definitions, and reference material. Reference notes are things you want to look up, not things you want to do (that's procedures) or things you want to track (that's threads).

## When to create a reference note

- A concept, pattern, or convention needs a stable definition
- You keep explaining the same thing to AI agents across sessions
- A topic is important enough to document but doesn't fit charters, threads, or artifacts

## How to create one

Ask your AI coding agent:

> "Write a reference note explaining [concept] so future sessions can look it up."

> "Document our [naming convention / deployment pattern / architecture decision] as a reference note."

## What makes a good reference note

- Self-contained: readable without other context
- Stable: doesn't change often (if it changes frequently, it might be a thread)
- Findable: clear title that matches how someone would search for it

## What reference notes are not

Reference notes are not procedures (step-by-step how-to), not charters (code-level documentation), and not artifacts (deep analysis with a date). They are the "look it up" layer.
