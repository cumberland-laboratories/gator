# Session Change Log

- Shared main-pane tab bar (`.gator-tabbar` / `.gator-tab`): full-width baseline, selected tab shown by weight plus underline, never colour alone (#72 checkpoint 1).
- Loop: Create / History tablist moved from the Loop sidebar into `#loop-tabbar` above the workspace body (`buildLoopTabs`, `ensureLoopPanels`, `applyTabState(container)`); panels stay in the sidebar; selection, polling, focus and Back/Forward unchanged.
- Tests: `_tab_state` pins the new tablist location; new `test_loop_tabbar_spans_main_pane` pins geometry, selected-state styling, and half-filled form survival.
- Charter: `scripts-dashboard-ui.md` Loop tabs and responsive-shell entries updated.
- Loop tabs stay inert until the first `/loops` response builds the panels (`switchTab()` guard), so a click during loading cannot render stale state or push a history entry ahead of the mount's landing entry; pinned by `test_loop_tabs_inert_until_loops_load` (mutation-checked).
- Significance check (TRIPWIRE: the #56 Loop-tab contract in `scripts-dashboard-ui.md` was rewritten). Steelman: (1) the tablist and its tabpanels now live in different containers, so `aria-controls`/`aria-labelledby` cross subtrees and assistive tech that ignores `aria-controls` loses the adjacency; (2) the tablist now exists before `/loops` resolves, a window the old sidebar-built tablist never had (found by this check; fixed by the inert guard above); (3) the new column wrapper (`.loop-workspace` → `.loop-workspace-body`) changes the flex/scroll chain and adds a fixed-height bar above both columns, reducing vertical space, notably under the 30vh mobile sidebar; (4) removing the `.loop-subnav*` CSS silently breaks any out-of-tree style or selector that targeted the sidebar tabs; (5) the less invasive alternative was restyling the tabs inside the sidebar. Compatibility: no public API, CLI, HTTP, schema or history-state change; `_state.view`, shell sub-state and Back/Forward entries are identical; the DOM change is internal to the Dashboard (only tests targeted the old location, updated here). Mitigations: tablist DOM order precedes its panels; polls never touch the tablist (`test_loop_tabs_survive_polls`); full Loop workspace + responsive-shell files pass. To be surfaced to the Architect before the final commit.
- Welcome workspace (#72 checkpoint 2): the sidebar logo is now a real `#brand-home` button ("Open Welcome") that opens a repository-independent `welcome` shell view. `views/welcome.js` renders four ARIA topics (What is Gator? · What Gator can do · Gatorize a repo · Start a session with Gator) in the shared main-pane tab bar, with fixed content linking to the public docs.
- Session-opening prompt: one copy control writes the exact vendor-neutral, layout-neutral prompt; "Copied" plus a polite status; Loop-pattern manual-copy fallback when the Clipboard API is missing or rejects. The prompt is never logged, stored, or put into history state; no fetch and no repository-context change from Welcome.
- Snapshot: `views/welcome.js` inlined by `build_snapshot()` (regex + block); `tests/test_snapshot.py` extended.
- Tests: new `tests/test_dashboard_ui/test_welcome_ui.py` (routing without repo mutation or requests, ARIA/keyboard and selected styling, exact copy, fallback, narrow width, Back/Forward and fresh-load default).
- Charters: `scripts-dashboard-ui.md` (Welcome entry with prompt TRIPWIRE, shell routing, logo button styling); `scripts-dashboard.md` (snapshot script order).

- Significance check, checkpoint 2 (TRIPWIRE: shell-owned history #56; `VIEW_META` gates `isShellEntry`). Steelman: (1) adding `welcome` to `VIEW_META` widens the set of restorable history entries; a Dashboard downgrade would ignore a `welcome` entry (Back skips it rather than restoring); (2) the logo changes from a decorative image to a named button, so screen readers now announce it and keyboard Tab stops on it, a new focus stop before the nav; (3) a local-first tool now carries outbound links to GitHub, which are dead offline and in snapshots (they carry no data: `noopener noreferrer`, plain navigation); (4) the copied prompt keeps the sketch's two line breaks, and some terminal agent UIs without bracketed paste treat a pasted newline as submit, which would send only the first line; (5) Welcome prose is hand-maintained in JS and can drift from README/docs. Compatibility: history-state shape unchanged (one new `view` value, `sub: null`); no API, CLI, HTTP or schema change; additive only. Mitigations: entries carry no prompt text (pinned); offline links are informational only; the Architect chose a single-line prompt (2026-10-10), which removes risk (4). To be surfaced to the Architect before the final commit.
